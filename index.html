Drawing with the Canvas

A short read before the task. Everything here gets used in the task, and this page stays open while you work, so you can come back to any section.

0. Try the editor

The editor on the right runs JavaScript. Type or paste these three lines under the starter code and press Run.

ctx.fillStyle = "steelblue";
ctx.fillRect(20, 20, 100, 60);
ctx.fillRect(150, 100, 60, 60);

You should see two blue rectangles. If you get an error instead, check for a missing quote or parenthesis. The error panel under the canvas tells you the line number. Delete the three lines when you're done, or leave them. Either is fine.

1. The canvas and the context

The page has one canvas element, 400 pixels wide and 300 tall. You never draw on the canvas directly. You draw through its 2D context, which the starter code already gets for you:

const canvas = document.getElementById("stage");
const ctx = canvas.getContext("2d");

ctx is the object you call for everything. Every rectangle, circle, and line is a call on ctx. Leave these two lines alone.

2. Coordinates

The origin (0, 0) is the top left corner. x grows to the right, like you'd expect. y grows downward, which is the part that trips people up. The bottom edge of this canvas is y = 300 and the right edge is x = 400.

A rectangle is described by its top left corner, then its width and height:

ctx.fillRect(x, y, width, height);

So this draws a box whose top left corner is 50 pixels over and 200 pixels down, 100 wide and 80 tall:

ctx.fillRect(50, 200, 100, 80);

Its bottom edge lands at y = 200 + 80 = 280. If you want a shape to sit on the bottom edge of the canvas, its y plus its height has to equal 300. Work backwards: a box 80 tall that touches the bottom needs y = 300 - 80 = 220.

3. Colors are settings, not arguments

Notice that fillRect has no color argument. Color is a setting on ctx called fillStyle. Set it once, and every fill after that uses it until you change it.

ctx.fillStyle = "seagreen";
ctx.fillRect(20, 20, 80, 80);     // green
ctx.fillRect(120, 20, 80, 80);    // also green, nobody changed the setting
ctx.fillStyle = "gold";
ctx.fillRect(220, 20, 80, 80);    // gold

Any CSS color works: names like "tomato", hex like "#3366ff", or "rgb(0, 200, 0)".

Two more things about how the canvas keeps state:

  • Shapes are painted in the order you call them. A later shape covers an earlier one where they overlap. If you draw a small shape and then a big one on top of it, the small one is gone.
  • strokeStyle is the same idea for outlines, and lineWidth sets how thick outlines are. Both stay set until you change them.

4. Rectangles

Three calls, same arguments:

ctx.fillRect(x, y, w, h);      // solid box
ctx.strokeRect(x, y, w, h);    // outline only
ctx.clearRect(x, y, w, h);     // erases that area back to blank

Outline example:

ctx.strokeStyle = "black";
ctx.lineWidth = 4;
ctx.strokeRect(100, 100, 120, 60);

5. Paths

Rectangles get their own shortcut calls. Anything else (triangles, lines, circles) is a path. A path is a set of points you describe first and then paint with fill() or stroke().

The pattern is always the same:

ctx.beginPath();          // 1. start a fresh shape
ctx.moveTo(200, 50);      // 2. put the pen down somewhere
ctx.lineTo(300, 150);     // 3. draw to the next point
ctx.lineTo(100, 150);     //    and the next
ctx.closePath();          // 4. connect back to the start
ctx.fill();               // 5. paint it, using fillStyle

That's a triangle. stroke() instead of fill() gives you the outline. You can call both.

The call people forget is beginPath(). Without it, the new points get added to whatever path you drew last, and fill() paints both shapes as one. If a shape comes out with a weird extra piece attached, or an earlier shape suddenly changes color, the fix is almost always a beginPath() in front of the new shape. The next section shows what that looks like.

6. Circles

A circle is a path too, made with arc:

ctx.beginPath();
ctx.arc(x, y, radius, startAngle, endAngle);
ctx.fill();

Two differences from rectangles:

  • x and y are the center of the circle, not a corner.
  • The angles are in radians, not degrees. A full circle is Math.PI * 2. Half a circle is Math.PI. Writing 360 also gives you a full circle, but only by accident (360 radians wraps around the circle many times), so use Math.PI * 2.

Full circle:

ctx.beginPath();
ctx.arc(200, 150, 50, 0, Math.PI * 2);
ctx.fill();

Bottom half (angles run clockwise starting from 3 o'clock):

ctx.beginPath();
ctx.arc(200, 150, 50, 0, Math.PI);
ctx.fill();

This is also where a missing beginPath() shows up most. Run this as is:

ctx.fillStyle = "firebrick";
ctx.beginPath();
ctx.moveTo(60, 200);
ctx.lineTo(160, 200);
ctx.lineTo(110, 120);
ctx.closePath();
ctx.fill();

ctx.fillStyle = "gold";
ctx.arc(300, 100, 40, 0, Math.PI * 2);   // no beginPath first
ctx.fill();

The circle grows a spike pointing at the triangle, and the triangle turns gold, because both shapes are still one path. Add ctx.beginPath(); above the arc line and run it again.

7. Rings

To draw a ring, put two circles in the same path and run the inner one backwards. The last argument of arc is counterclockwise. When the inner circle goes the opposite direction from the outer one, fill() treats the inside as a hole and leaves it empty:

ctx.fillStyle = "crimson";
ctx.beginPath();
ctx.arc(200, 150, 100, 0, Math.PI * 2, false);   // outer edge
ctx.arc(200, 150, 70, 0, Math.PI * 2, true);     // inner edge, backwards
ctx.fill();

Whatever was behind the ring shows through the middle. If the middle fills in solid, the inner arc is missing the true at the end.
